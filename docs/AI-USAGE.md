# AI 在这个项目里用在哪，以及为什么

> 本文回答一个具体问题：**合规卫士需不需要 AI？需要的话，用在哪个环节？**
>
> 结论先给：**需要，但只用一个环节——改写。判定绝不能交给 AI。**
> 这个边界不是折中，是这个工具能不能被信任的前提。

---

## 一、一句话分工

| 环节 | 谁来做 | 为什么 |
|---|---|---|
| **判定**：这句话违不违规、算几级、扣几分 | **规则引擎** | 需要确定、可复现、可解释、有法条依据 |
| **改写**：把违规的说法换成既合规、又保住卖点的说法 | **语言模型** | 需要语言能力，不是查表能力 |

画成流程：

```
文案 ──► 规则引擎（Aho-Corasick + 变异归一 + 语境守卫）
          │
          ├─► 命中清单（词条 / 法条来源 / 等级 / 替换词）   ← 这是"结论"
          │
          └─► 合规分 + 风险等级 + 高亮预览                  ← 用户直接可用
                    │
                    └─► 【可选】AI 改写
                          输入：原文 + 上面那份精确命中清单
                          输出：改写后文案 + 逐处改动对照
```

注意箭头方向：**AI 在规则引擎的**下游**，它拿到的输入是已经定好的结论，它的产出不再回头影响判定。**

---

## 二、为什么判定不能交给 AI

这不是"AI 不够强"的问题，是**判定这个岗位的性质**决定的。

### 1. 判定要可复现，模型给不了

同一条文案今天判 78 分，明天还得是 78 分。同一个人昨天发的和今天发的，判罚必须一致。

模型不是这样工作的。把同一句话问两次，它可能给两个答案——`temperature` 调到 0 也只能减少、不能消除这种情况。而一个"每次结果都不太一样"的合规工具，用户第二次用就不敢信了。

**规则引擎天然满足这一点**：输入确定 → 输出确定。这一条有回归测试守着（`tests/test_engine.py`、`tests/corpus/`）。

### 2. 判定要可解释，模型解释不了

用户看到「扣 5 分」，一定会问「凭什么」。

规则引擎能答：命中《广告法》第九条第（三）项的「国家级」表述，来源 `ad_law`，等级 high，这是可追溯、可核对的。

模型只能给你一段看起来有理的话，但你无法验证它是不是真的对应某条法规——它可能引一条根本不存在的法条。**在合规场景里，一个编出来的法条依据比没有依据更危险。**

### 3. 判定的两类错误，代价不对称

| 错误类型 | 后果 | 用户会怎样 |
|---|---|---|
| 误报（把合规的判成违规） | 文案被无谓改掉，或者用户不再信任工具 | 用几次就弃用 |
| 漏检（把违规的判成合规） | 发出去被限流、封号、甚至行政处罚 | 直接造成损失 |

模型在这两个方向上都不可控：它会漏（尤其是没见过的变体表达），也会编（凭空发明根本不存在的违规）。

**我们的做法是把两类错误都变成可测量的数字**，然后用测试钉住：

```
合规语料 31 条 → 误报率 0.0%
违规语料 30 条 → 漏检率 0.0%  （仅提示率 10%）
```

这两个数字写在 `tests/corpus/__init__.py` 里，任何改动一旦让误报率超过 5%，CI 直接红灯。模型做不到这种承诺。

### 4. 一个具体的例子

「第三位伤员已送医」这句话里有个「第三位」。

- 规则引擎：识别出这是**序数表达**（`第 + 数词 + 结构量词`），落在豁免区间内 → 不报。
- 如果把判定交给模型：它很可能因为看到「第三」就报「排名宣称违规」——因为它是靠"像不像违规"来判断的，不是靠语法。

反过来，「销量第3名」里的「第3名」，我们**故意不豁免**——因为在广告语境里，这就是排名宣称，是《广告法》明确禁止的。

一个字之差（`位` vs `名`），背后是明确的判断，不是模型的即兴发挥。这类边界靠提示词调不出来。

## 三、为什么改写必须交给模型

这个环节反过来——规则引擎真的做不了。

规则库能告诉你「《广告法》禁用『最』字」，能给出替换词「较」「更」。但它给不出这句话：

> 原文：保签包过，不过全额退款，成功率 100%
>
> 改写：协助准备申请材料、按流程递交，并对可行路径做前置评估；材料准备与递交进度全程跟进。

这句话里做了三件事，全都需要语言能力：

1. **把结果承诺换成过程表述**（保签包过 → 协助准备、按流程递交）
2. **把虚假数字整个拿掉，而不是替换**（成功率 100% → 无对应表述）
3. **把被削掉的卖点用合规方式补回来**（"全程跟进"——你仍然在说自己有服务，只是不再承诺结果）

第 3 条尤其关键。很多工具（和很多人）改到这里就变成了一句废话：「我们做移民的」。**合规不等于把文案改得没有说服力**，这个平衡只有语言模型能做。

## 四、提示词是怎么把这个边界焊死的

光在文档里写"不要让 AI 判定"没有用——模型看不到文档。所以这句话必须进提示词，而且要写得比"要做什么"更详细。

`guardian/llm/prompts.py` 的核心约束（两端共用同一份）：

```
## 你的唯一任务
把下面这段文案**改写**到合规。**不要做合规判定**——违规点已由规则引擎
精确找出并列在下方，你只需要按清单逐处改写。

## 为什么判定不交给你
规则引擎的判定确定、可复现、每条都能追溯到法条；模型做判定会漏检、会
凭空发明违规、同一句话问两次给两个答案。所以：
* **不要**新增清单以外的"我觉着也违规"的判断
* **不要**删除清单以外的任何内容
* **不要**在输出里讨论这段文案合不合规，只给改写结果
```

还有一条容易被忽略但很重要的：

```
## 拿不准的时候
如果某处无法在不失真的前提下改写（例如改了就构成虚假宣传、或必须补充
真实资质才能说清），把它如实写进 unresolved，说明**为什么改不了**和
**需要补充什么信息**。**不要硬凑一个假方案**。
```

为什么要有这条？因为模型的默认行为是"讨好"——你让它改写，它一定会给你一个改写版本，哪怕那个版本是编的。**一个诚实的"这句需要人工确认"，比一个编出来的合规说法有用得多。**

这条约束的效果是可验证的：`tests/test_rewrite.py::TestPromptBoundary` 会检查提示词里这几句还在不在。删掉任何一句，测试就红。

## 五、没有 AI 的时候，产品还完整吗

**完整。** 这是设计底线，不是口号。

三层降级，每层都是可用的产品：

| 情况 | 用户得到什么 |
|---|---|
| 没配任何模型（默认） | 完整检测：命中清单 + 分级 + 合规分 + 高亮预览 + 导出报告。**一个字的功能都不少。** |
| 想用 AI，不想配 key | 点「复制改写指令」——把规则引擎的精确命中 + 改写约束打包成一段文本，粘到任意 AI（豆包 / DeepSeek / ChatGPT）里就能拿到改写。**零配置、零注册、零成本、零隐私风险。** |
| 配了本地 Ollama 或云端 API | 检测完点「AI 改写」直接出结果，附逐处改动对照 |

第二条（我们内部叫 **BYO-AI**，Bring Your Own AI）是个人认为最划算的设计：

- 用户不需要在这台电脑上装 Ollama（几个 GB 的模型）
- 文案不需要经过我们的服务器（我们也确实没有服务器）
- 用什么模型由用户自己决定，也不用为此付费
- 它顺便让整个 Web 体验页可以**纯静态部署**——没有后端，就没有运维、没有数据泄露面

代价是用户要多一步粘贴动作。这个交换我们认为值得。

有测试钉住这条底线：

```python
def test_detection_unaffected_by_ai_failure(self):
    """AI 挂掉后，规则检测的分数与命中必须一模一样。"""
    # 故意配一个必然连不上的本地地址，再跑一次检测
    # 断言 score 与 findings 数量完全不变
```

## 六、这些决定带来了什么

按上面的分工做完之后，有几个副作用值得说：

**1. 响应时间是毫秒级，且不随 AI 状态波动。**
检测不依赖网络。AI 改写（本地 7B 模型）要 30~90 秒，但它是一个用户主动点的独立动作，不阻塞检测。

**2. AI 服务可以随时挂，产品不降级。**
调用失败不是"报错"，而是"换条路"——弹窗问你要不要复制改写指令走 BYO-AI 路径。

**3. 改写结果可复核。**
因为输入是确定的命中清单，每一处改动都能对应回一条规则。UI 上会并排显示「改前 → 改后」，用户不必盲信模型。

**4. 可以对外说清 AI 在哪。**
"我们的 AI 只做改写，不做判定"——这句话本身就是产品差异点。市面上多数"AI 合规检测"是把整段文案丢给模型让它判断，那种做法我们明确不用。

---

## 七、一句话总结

**判定是"作证"，改写是"说话"。作证得确定、可追溯，所以归规则引擎；说话要灵活、得体，所以归模型。**

把这两件事混在一起交给同一个东西，是大多数同类工具最根本的设计错误。
